The problem

One request froze an AI server, and its health check stayed green

SGLang runs AI models for many users at once. In our test, one request reached the front of the line and never moved, so everyone behind it waited too.

What went wrong

Two checks that disagree by one slot

Picture the server's memory as 600 seats, one for every word the AI reads or writes. The planner leaves 1 seat spare. The guard at the door wants more than 1, so it turns the request away from a room with nobody else in it.

Why it stays stuck

Shorter questions and waiting both fail

Any seats you free up, the planner gives to the answer, so 1 seat is spare whatever the question length. The room is already empty, so nobody will ever leave and make space.

Why nobody caught itIt needs three things at once: a request for the longest possible answer, a memory cache (normally on) switched off, and an idle server. Even then the health check stays green.
The fix

Both fixes pass the test. One of them removes a safety margin.

The guard keeps a spare seat to absorb awkward cases when memory gets handed out. Fix A throws that seat away. Fix B has the planner leave one more seat and leaves the guard alone, which is the one-line change we made.
