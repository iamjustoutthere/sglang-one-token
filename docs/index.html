1 · What is the problem?

The server freezes while every check says it's healthy

  • One request gets stuck at the front of the line.
  • Everyone behind it waits, forever.
  • No crash, no error, status stays green.
  • That's worse than a crash. Crashes get noticed and restarted.
  • Only fix: a person spots it and cancels the request.

2 · When and why does it happen?

Two parts of the code disagree by one

Why
  • Memory holds 600. The question takes 560.
  • Part 1 sizes the reply to 38, leaving 1 free.
  • Part 2 only starts a request with 2 free.
  • Nothing else is running, so nothing frees up. It retries forever.
When
  • Longest-possible reply, idle server, memory cache off.
Why nobody caught it
  • Each part passes its own tests. The bug lives between them.
  • "Keep these consistent" was only a code comment.

3 · What does formal verification catch?

A promise in a comment can't be checked. A promise in math can.

  • The promise: whatever part 1 allows, part 2 accepts.
  • A prover checks it for every input, not a sample.
  • Old code: fails at once, names the stuck case (38 / 1 / no).
  • Our fix: passes. Two separate provers agree (K and Lean).
  • Checked on every change, it would have blocked this bug on day one.
  • Next: prove it on SGLang's real code, not our copy of the math.
