1 · What is the problem?

The AI server freezes and says "all good"

  • SGLang is free software that companies use to run AI chatbots for many people at once.
  • One request can get stuck at the front of the line and never start.
  • Everyone behind it waits too. Nothing crashes and no error appears.
  • The status light stays green, so no alarm goes off.
  • The only way out is for a person to notice and cancel the stuck request.

2 · When and why does it happen?

Two sensible rules that can never both be met

Why
  • Think of the server's memory as a train with 600 seats.
  • The booking office fills it so that exactly 1 seat stays empty.
  • The conductor only leaves when 2 or more seats are empty.
  • Nobody else is on board, so nothing ever changes. The train never leaves.
When
  • Someone asks for the longest possible reply, on a quiet server with one memory-saving feature switched off.
Why nobody caught it
  • Each rule looks right alone and passed its own tests.
  • The promise to keep them in sync was only a code comment.
  • Everyday traffic never triggers it, and the light stays green.

3 · What does formal verification catch?

Every usual safety net missed it. A proof doesn't.

  • We write the promise down as math: "everything the booking office sells, the conductor accepts."
  • A computer then checks it for every possible case, not a sample.
  • On the old code it fails at once and shows the exact stuck case: 38 seats saved for the reply, 1 empty, conductor says no.
  • Checked on every change, it would have failed the day the bug went in, before anyone was affected.
  • Our one-line fix passes, confirmed by two separate proof tools, K and Lean.
  • Still to do: we proved a hand-written copy of the math, not SGLang's own code. That's our next step.
